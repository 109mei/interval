# INTERVAL — 糧と期限の盤

独自4駒を期間契約で召喚する、7×7のターン制ゲームです。招待リンクでのフレンド対戦、ローカル2人対戦とCPU戦を実装しています。白黒の立体駒はThree.jsで描画し、WebGLが使えなければ2Dへ切り替えます。

## はじめ方
普通のURLではホームが開きます。CPU・この端末で2人・フレンド対戦から選び、開始ボタンを押してください。CPUは白を人が操作し、黒を自動で操作します。この端末で2人では両側を交互に人が操作します。
対局中の「ホーム」は確認して戻ります。端末内・CPU戦は同じページ内で一時停止・再開でき、再読み込みするとリセットされます。フレンド対戦は席を保持しますが、相手の対局進行は止まりません。退出は別の確認操作です。

## 遊び方
- 初期盤面は双方の王（固定コア）だけです。他の駒は糧を使って召喚します。
- 敵の固定コア（◆）へ攻撃可能な駒を移動させれば勝利。
- 毎手番に糧4。保有上限はありません。初期12に初回収入を加え、各側の初手は16。
- 自陣の手前3列の空きマスに、期間1〜5ターンで召喚。中央の1列と相手側には召喚できません。費用は単価×期間を前払い。
- 1手番に召喚、移動、交換、パスから1行動。パスも選択後に確定を押します（連打による誤操作を防ぐため）。
- 召喚した番はその駒の期間を減らしません。以後は自分の手番末に自軍全駒を1減らし、0で退場。動かなかった駒も減ります。
- 捕獲報酬は、取った敵の単価×捕獲時の残り期間。自然退場では獲得しません。
- コア捕獲は期限処理より優先。連続6パスまたは200手で引き分け。
- バスティオン（単価1）: 動かない壁。リンクで交換できる。
- カーヴァー（単価3）: 縦横1マスから直角に1〜2マス。途中に駒がある経路は不可。
- リーパー（単価2）: 隣接する駒を8方向に飛び越え、直後へ着地。足場は残し、着地点の敵だけ取る。
- リンク（単価1）: 縦横に隣接する味方と位置交換。捕獲は不可。期限を延長しない。

## フレンド対戦
「フレンド対戦」→「部屋をつくる」→招待リンクを1人に送る→相手が参加→2人が準備完了、で開始します。
部屋は24時間有効です。同じブラウザでは再読み込みから復帰できます。返信を受け取れなかった操作は再接続ボタンで同じ送信IDの結果を確認し、二重実行を防ぎます。Cookieを消すと席に戻れません。招待リンクは対戦相手以外に渡さないでください。招待リンクを持った最初の参加者が黒になります。

## 実行・構成
Node.js 24以降で npm ci、npm run dev。開発サーバーではCPU・同じ端末での対戦を使えます。フレンド対戦はD1バインディングのあるSites Workerで動きます。
npm run build は dist/client と、fetchハンドラーを持つ dist/server/index.js を生成します。Workerにクライアントの公開アセットも含めるため、別のアセットサービスは不要です。
DBスキーマは db/schema.ts、生成済みマイグレーションは drizzle/。スキーマ変更時は npm run db:generate。実行時DDLはありません。

## 安全性
公開のゲーム画面と、2席だけが操作できる部屋を分けています。席の権限はSecure / HttpOnly / SameSite=StrictのCookie、DBにはハッシュのみ。招待はURLフラグメントで受け取り、参加後は消します。共有エンジンによるサーバー側検証、バージョンCAS、リクエストIDによる再送防止を使います。
同じブラウザは同じ席になるため、2人対戦のテストには独立したブラウザプロファイルが必要です。

さらに追加した500件の自動シナリオ（アクセシビリティ・モーション重点）は [docs/REVIEW-500-SCENARIOS.md](docs/REVIEW-500-SCENARIOS.md) と各ケース記録にあります。実スマホ500回の検証や500回の公開を意味するものではありません。
CPU・端末内対戦は再読み込みでリセット。CPUは有効期間を踏まえて候補を絞り、相手の全応手と次手のコア捕獲を確認します。通常は専用Web Workerで計算し、再試合時は古い計算を破棄します。通信切断は自動パスや投了になりません。

ローカル最適化の計測・回帰検証・未確認範囲は [docs/PERFORMANCE.md](docs/PERFORMANCE.md) に記録しています。ホームと2DではThree.jsを読み込まず、3D要求時に読み込みます。読み込み中も2Dの盤で操作でき、読み込み後は現在の盤面を引き継ぎます。

最適化後の追加200件は [docs/REVIEW-200-SCENARIOS.md](docs/REVIEW-200-SCENARIOS.md) に記録しています。読み込み・連続入力・通信復旧・表示終了処理を重点にしたローカル自動検証で、実機200回のプレイや公開を意味しません。
